# 比特浏览器管理模块设计

## 范围

采用 Python 模块与 SQLite 本地存储。第一期完成 bitbrowser 管理能力；facebook、instagram 建立独立包边界，后续管理各自账号、Cookie 与自动化任务，通过 bitbrowser 获取窗口及连接信息。本期不开发 Web 管理页面或社交平台操作。

现有 bit_api.py、bit_playwright.py、bit_selenium.py 是示例，保留供参考，不自动执行其中的创建、启动和删除动作。当前目录不是 Git 仓库，不进行提交。

Git 操作由用户本人负责。本项目开发过程中禁止执行任何会修改 Git 状态或远端的命令，包括 add、commit、push、pull、merge、rebase、checkout、switch、reset、branch、tag 和 worktree。

## 模块

- bitbrowser/client.py：统一 HTTP 客户端，可配置服务地址（默认 http://127.0.0.1:54345）与超时，校验 HTTP 状态、JSON 和业务 success 字段。修改请求不自动重试，防止重复创建。
- bitbrowser/groups.py：分组增删改查、窗口分组调整。
- bitbrowser/browsers.py：窗口增删改查、打开关闭、批量打开关闭、指纹与 Cookie 接口封装。批量操作限制并发，逐个返回成功或失败。
- bitbrowser/proxies.py：代理导入、修改、禁用、检测、选择与绑定规则。
- bitbrowser/storage.py：SQLite 代理池、窗口与分组映射、绑定与操作状态。
- bitbrowser/manager.py：协调数据库约束与远程接口，为业务模块提供受约束的管理入口。
- facebook/、instagram/：独立包，文档明确当前未实现账号自动化。

比特浏览器底层接口与本项目管理入口分开：底层客户端负责接口调用，代理唯一性由管理入口保证。文档逐项核对已封装的端点，不把通用请求方法当成全部接口已经实现。

## 代理选择开关

配置 allocation_mode，支持 manual、sequential、random 三种模式；允许调用时覆盖默认配置。

- manual：调用方明确指定 proxy_id。
- sequential：从当前分组尚未占用的启用代理中，按稳定的代理 ID 顺序选择。
- random：从相同候选集中随机选择。

自动分配发生在创建窗口、首次补充绑定或显式更换代理时。启动已有窗口沿用持久绑定，不因 random 模式在每次重启时更换。候选耗尽时报错，不回退直连，也不复用本组已占用代理。

## 分组内唯一性

每个窗口恰好绑定一个代理；同一分组不可重复使用相同代理 IP，不同分组可以复用。未分组窗口视为同一个默认分组，不能借空 group_id 绕过约束。

代理端点（协议、主机、端口、认证）与出口 IP 分开存储。相同出口 IP 即使端口或凭据不同，在同一分组仍视为冲突。为兑现 IP 不重复的要求，分配前检测并获取真实出口 IP；检测失败或无法确定出口 IP 的代理不参与分配。域名代理不能仅按域名字符串判重。动态代理仅能保证检测时观测到的出口 IP，无法保证供应商随后不变更；第一期以固定出口代理为支持范围。

数据库使用分组与出口 IP 的组合唯一约束；并发选择通过事务预占，避免两个窗口同时获得同组相同 IP。关闭窗口保留占用，删除窗口或显式解绑成功后才释放。

移动窗口到另一分组时先检查目标分组：原 IP 未占用则保留；发生冲突则返回明确错误，由调用方显式更换代理后再移动，避免无意更换账号网络环境。

## 一致性与异常

代理绑定和窗口创建先预占，再调用远程接口，成功后确认绑定。远程明确失败时释放预占；超时等结果不确定情况保留待核对状态，禁止盲目释放导致重复分配。再次操作前读取远程状态进行核对。

启动窗口前检查绑定、代理启用状态、出口 IP 与远程代理配置。检测到外部修改或出口变化则停止启动并提示重新核对。运行中的窗口不允许直接替换代理。禁用代理阻止之后的启动，不自动关闭已运行窗口。

代理凭据及 Cookie 不输出至日志；数据库属于敏感本地文件，不加入版本控制。删除分组前要求分组无窗口，避免隐式批量变更。

## 验证与验收

使用模拟 HTTP 响应验证接口参数、分页、超时和业务失败；使用临时 SQLite 验证三种模式、同组冲突、跨组复用、出口 IP 判重、无分组窗口、代理耗尽与并发预占。

测试还覆盖远程失败回收、超时保留待核对、窗口关闭不释放代理、移动分组冲突、禁用代理和批量部分失败。真实联调需要可访问的本地比特浏览器服务及测试代理；模拟测试通过不等于真实联调通过。
