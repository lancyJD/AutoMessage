# Instagram 全自动发帖设计

## 目标

在现有 Python、Playwright 和 BitBrowser 能力上增加 Instagram Feed 自动发帖功能。调用方提供账号资料、一个或多个素材地址、标题和内容后，程序完成登录、素材准备、页面上传、配文填写、公开分享和结果确认。

首期只支持 Instagram Feed 普通帖子，包括单张图片、单个视频及多图片/视频轮播；不包含 Reels 和 Story。

## 输入与输出

命令行输入：

- `--account-file`：账号 Markdown 文件，默认使用现有账号文件。
- `--media`：可重复传入，或一次传入多个素材地址；保持输入顺序。
- `--title`：可选，支持普通文字和表情。
- `--content`：可选，支持普通文字和表情。
- `--relogin`：需要时关闭该账号由程序管理的旧窗口并重新登录。

最终配文规则：

- 标题和内容都有值：`标题 + 两个换行 + 内容`。
- 只有一项有值：只使用该项。
- 两项均为空：允许无配文发布。

成功时输出结构化发布结果，包括状态、账号、素材数量和可获取到的帖子 URL。失败时输出阶段、错误类别和不包含敏感信息的说明。日志不得包含密码、Cookie、2FA 密钥、完整认证请求头或验证码。

## 技术方案

采用 Playwright 驱动 BitBrowser 中的 Instagram 网页发布流程，不直接实现 Instagram 私有上传接口。定位优先使用 `role`、可访问名称、标题文字和稳定表单属性，动态 class 仅作为最后兜底。

新增模块：

- `instagram/media.py`：解析和准备素材。
- `instagram/posting.py`：发帖状态机与结果模型。
- `scripts/publish_instagram_post.py`：命令行入口和依赖组装。

复用模块：

- `bitbrowser`：创建、打开和连接浏览器环境。
- `instagram/login.py`：Cookie 与账号密码登录。
- `instagram/totp.py`：需要 2FA 时生成当前六位验证码。

登录模块需要扩展账号模型以读取 `two_factor_secret`，并在 Instagram 明确显示两步验证输入页时自动填写 TOTP。普通验证码、challenge、身份确认或其他风控页面不尝试绕过，立即返回需要人工处理。

## 素材处理

素材地址支持：

- Windows 本地绝对路径。
- `http://` 或 `https://` URL。

本地素材必须存在且为普通文件。网络素材下载到任务专属临时目录，设置连接与读取超时、响应大小上限，并根据响应 MIME、文件签名和扩展名确定文件类型。重定向后的协议仍必须为 HTTP/HTTPS。

允许类型以 Instagram 网页文件选择框实际支持范围为基准：JPEG、PNG、AVIF、HEIC、HEIF、MP4、MOV。文件数量和大小在提交前检查；若网页或账号对某组合不支持，返回素材校验或上传阶段错误，不自动删减素材。

任务结束后清理本次下载的临时文件，不删除调用方提供的本地文件。

## 页面发布状态机

1. 准备并校验所有素材，保留输入顺序。
2. 通过 BitBrowser 打开或复用该账号的环境，并完成登录。
3. 打开 Instagram 首页，点击可访问名称为“新帖子”或“创建”的入口。
4. 等待“创建新帖子”对话框，将所有素材一次性设置到 `input[type=file][multiple]`。
5. 等待素材预览完成；出现“裁剪”阶段时点击“继续”。
6. 出现“编辑”阶段时点击“继续”。
7. 在“创建新帖子”配文阶段找到文本框，填入合并后的配文。
8. 点击“分享”一次，随后进入结果确认阶段，不再重复点击。
9. 等待明确成功提示；尽可能从页面获取新帖子 URL。

每个阶段都有独立超时和诊断名称。页面语言兼容中文和英文文案；稳定属性定位优先于语言文本。

## 防重复与重试

公开发布属于不可自动回滚操作。程序只允许在点击“分享”之前重试可安全步骤。一旦点击分享：

- 不因超时自动重新提交。
- 如果成功状态不明确，返回 `unknown`，提示人工检查账号主页。
- 同一进程内不会再次点击分享。

每次命令默认只创建一个帖子。需要发布第二个帖子时必须再次运行命令并明确提供下一条文案。测试文案按需求文档给出的顺序使用，不在程序中硬编码。

## 错误处理

错误按阶段归类：

- `input`：路径、URL、格式、数量或下载错误。
- `login`：账号密码失败、2FA 失败或登录状态无法确认。
- `needs_human`：challenge、验证码、身份确认或账号风控。
- `upload`：素材未进入预览或 Instagram 拒绝素材。
- `compose`：无法找到配文框或继续按钮。
- `publish`：分享前页面拒绝操作。
- `unknown`：已经点击分享但无法确认成功或失败。

失败时保留 BitBrowser 窗口供人工检查；仅关闭本次代码明确创建且配置为自动关闭的临时资源。不得关闭用户原本打开的其他环境。

## 测试策略

单元测试：

- 配文合并，包括空值、表情和多语言。
- 本地路径与 HTTP/HTTPS 分类、文件类型和顺序。
- 网络下载超时、重定向、大小限制与临时文件清理。
- 页面状态机使用模拟 Playwright 页面，覆盖图片、视频、多素材、2FA、challenge、上传失败以及分享后状态未知。
- 验证分享按钮最多点击一次，未知结果不会自动重发。
- 验证日志和结果不包含账号密码、Cookie、TOTP 密钥或验证码。

集成测试：

1. 启动 BitBrowser 客户端。
2. 使用受控账号文件进行登录；Cookie 不可用时使用账号密码，若出现标准 2FA 页面则自动填写 TOTP。
3. 使用需求文档中的本地测试素材和第一条测试内容公开发布一次。
4. 检查成功提示与账号主页中的新帖子。
5. 只有第一次因开发验证确实需要再次发布时，才使用需求文档中的下一条测试内容重新执行；不对结果未知的任务自动补发。

## 验收标准

- 一条命令能够使用本地素材完成一次公开 Feed 发布。
- 同一入口支持 HTTP/HTTPS 素材，并在下载后完成发布。
- 支持单个及多个图片/视频素材，并保持传入顺序。
- 标题和内容按照约定合并，文字、表情和韩文不乱码。
- 标准账号密码与 TOTP 登录可自动完成；风控验证停止并提示人工处理。
- 点击分享后不会自动重复提交。
- 自动化测试通过，真实集成测试能在目标账号主页确认帖子存在。

## 不在首期范围

- Reels、Story、直播或定时发布。
- 图片裁剪、滤镜、视频剪辑、封面选择和配乐。
- 自动绕过验证码、challenge 或账号风控。
- 多账号批量调度、后台任务队列和失败自动补发。
- 直接调用或维护 Instagram 私有上传接口。
