# 自动素材下载模块设计

## 1. 背景与目标

项目需要新增一个独立的素材下载模块，参考 `yt-dlp` 官方项目并通过其 Python API 获取公开页面的媒体与元数据。模块需要支持单链接、批量链接和关键词搜索三种入口，将素材持久化到固定目录，并为每条内容生成一个可供后续自动发帖流程读取的 `.text` 元数据文件。

本功能不会复制或维护 `yt-dlp` 的内部 extractor 源码，而是把 `yt-dlp` 作为依赖封装。这样可以沿用上游对站点变化的适配能力，并降低后续升级成本。

## 2. 功能范围

### 2.1 支持的输入模式

1. 单链接：接收一个 YouTube、TikTok 或 Instagram 内容链接。
2. 批量链接：从文本文件读取多个链接，忽略空行，并对重复链接去重。
3. 关键词搜索：使用 `yt-dlp` 原生的 YouTube 搜索 extractor，默认下载前三条结果，允许通过参数修改数量。

### 2.2 平台边界

- YouTube：支持单链接、批量链接和关键词搜索。
- TikTok：支持单链接和批量链接。
- Instagram：支持单链接和批量链接。
- TikTok 和 Instagram 的关键词搜索不属于 `yt-dlp` 当前原生能力，本模块不额外引入浏览器自动化或非官方搜索接口。
- 不绕过 DRM、付费墙、登录权限或平台访问控制。调用方应确保有权下载和使用目标内容。

## 3. 模块结构

计划新增：

- `instagram/material_downloader.py`：领域模型、参数校验、`yt_dlp.YoutubeDL` 封装、落盘与元数据生成。
- `scripts/download_material.py`：命令行入口，提供 `url`、`batch`、`search` 三个子命令。
- `tests/test_material_downloader.py`：通过依赖替身测试配置、路径、去重、元数据与异常处理，不在常规单元测试中访问外网。

现有 `instagram/media.py` 继续负责自动发帖流程中的临时直链下载。新模块负责长期保存素材，两者职责隔离，避免改变现有发帖行为。

## 4. 命令行交互

```powershell
python -m scripts.download_material url "https://example.com/post"
python -m scripts.download_material batch "links.txt"
python -m scripts.download_material search "旅行风景"
python -m scripts.download_material search "旅行风景" --count 5
```

默认配置：

- 输出目录：`C:\Users\DELL\Pictures\sucai`
- 搜索结果数：3
- 搜索平台：YouTube

`--output-dir` 可用于测试或以后迁移，但未传入时必须使用上述固定目录。`--count` 必须是大于零的整数，并只对 `search` 子命令生效。

## 5. 下载流程

### 5.1 单链接

1. 校验输入为 HTTP 或 HTTPS URL。
2. 调用 `YoutubeDL.extract_info(..., download=True)`。
3. 归一化 extractor 返回结果，识别单条内容、播放列表和多媒体条目。
4. 收集实际落盘的媒体路径。
5. 下载全部成功后生成对应 `.text` 文件。
6. 返回结构化结果，供命令行输出成功或失败信息。

### 5.2 批量链接

1. 以 UTF-8 读取链接文件。
2. 去除空白、跳过空行，并按首次出现顺序去重。
3. 每个链接作为独立任务执行；单项失败不终止其余任务。
4. 最后输出总数、成功数、跳过数和失败数。

### 5.3 关键词搜索

1. 校验关键词非空，数量大于零。
2. 构造 `ytsearch{count}:关键词` 输入。
3. 下载搜索结果中的实际视频条目。
4. 每个结果独立建立目录并生成自己的 `.text` 文件。

## 6. 目录与文件命名

根目录固定为：

```text
C:\Users\DELL\Pictures\sucai
```

每条内容使用独立目录：

```text
sucai/
  TikTok_旅行风景_748123456/
    旅行风景.mp4
    TikTok_旅行风景_748123456.text
```

目录和元数据文件采用：

```text
平台_标题_素材ID
```

命名处理规则：

- 删除或替换 Windows 文件名非法字符 `< > : " / \ | ? *`。
- 去除末尾的点和空格。
- 限制标题片段长度，给平台、ID、扩展名保留空间。
- 标题为空时使用 `untitled`。
- 平台为空时使用 extractor 名称，仍为空则使用 `unknown`。
- 素材ID为空时使用来源URL的稳定摘要，避免随机命名。

同一平台与素材ID已经存在且元数据完整时，默认跳过重复任务。不得仅凭标题判断重复。

## 7. 元数据文件

每条内容生成一个 UTF-8 编码的 `.text` 文件：

```text
标题:旅行风景
内容:原帖描述或视频简介
素材:C:\Users\DELL\Pictures\sucai\TikTok_旅行风景_748123456\旅行风景.mp4
```

图集或一条内容产生多个媒体文件时，所有绝对路径写入同一行，并以英文逗号分隔：

```text
素材:C:\...\001.jpg,C:\...\002.jpg
```

字段映射：

- 标题：优先使用 `title`，缺失时为空。
- 内容：优先使用 `description`，缺失时为空。
- 素材：只写已成功落盘且位于任务目录中的媒体文件绝对路径。

元数据先写入同目录临时文件，再通过原子替换生成最终 `.text` 文件，避免进程中断留下看似完整的记录。

## 8. yt-dlp 集成策略

项目通过 Python 依赖使用 `yt_dlp.YoutubeDL`，不通过 shell 拼接外部命令。主要配置包括：

- 输出模板限定在当前任务目录内。
- 使用 progress hook 收集下载状态和最终文件名。
- 允许播放列表或图集产生多个媒体文件。
- 禁止读取用户机器上的全局 yt-dlp 配置，保证项目行为可预测。
- 保留合理的重试和断点续传能力。
- 默认选择适合本地使用的最佳可用格式。

某些站点或格式需要 FFmpeg 合并音视频或执行后处理。检测到缺失时应给出明确错误信息，不应把不完整结果标记为成功。

## 9. 安全与路径约束

- 所有输出路径解析后必须位于指定输出根目录内，防止标题或上游元数据造成目录穿越。
- 批量输入只接受 HTTP/HTTPS URL。
- 日志不得输出 Cookie、Authorization 请求头或其他登录凭据。
- `.text` 文件只记录本地素材路径，不保存认证信息。
- 删除临时文件时仅允许操作当前任务目录内由模块创建的明确路径。

## 10. 日志与错误处理

日志至少包含：

- 任务开始、输入模式和目标数量。
- 当前条目序号、平台、标题或素材ID。
- 下载进度和最终保存路径。
- 重复跳过原因。
- 单项失败原因。
- 批量汇总：总数、成功、跳过、失败。

异常分类至少包括：输入错误、不支持的URL、网络或限流错误、需要登录、下载失败、FFmpeg缺失、文件系统写入失败。命令行在存在失败任务时返回非零退出码；批量模式仍应先处理完其他独立任务。

## 11. 测试与验收

### 11.1 自动测试

- 单链接会向 `YoutubeDL` 传入正确配置。
- 批量文件能过滤空行并保持顺序去重。
- 搜索命令正确生成 `ytsearch3:`，自定义数量生效。
- 文件名清理能处理 Windows 非法字符和空标题。
- 元数据严格生成三行，并能记录多个素材绝对路径。
- 下载未完成或失败时不生成最终 `.text`。
- 已完成的同平台同素材ID任务会被跳过。
- 上游返回的路径不能逃逸输出根目录。
- 批量单项失败不会阻止后续任务。

### 11.2 手动验收

在用户有权下载的公开内容上分别验证：

1. 一个 YouTube 链接。
2. 一个 TikTok 链接。
3. 一个 Instagram 链接。
4. 一个包含重复项的批量链接文件。
5. 一个默认数量为3的 YouTube 关键词搜索。

验收时检查素材文件真实存在、`.text` 文件名符合规则、三项字段正确、素材路径均为绝对路径，并确认重复运行不会产生重复副本。

## 12. 暂不包含

- TikTok、Instagram 关键词搜索。
- 浏览器自动化搜索或登录接管。
- DRM、付费或私密内容绕过。
- 下载后自动发布到 Instagram。
- 图形界面、后台任务调度和数据库记录。

后续可以让自动发帖模块读取这里生成的 `.text` 文件，但应作为单独需求设计和实现。
