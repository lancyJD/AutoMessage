## 目标

在现有 Chrome 扩展的粉丝采集页面中增加第二种采集模式。默认保持“获取粉丝”；用户可切换到“获取帖子互动用户”，按发布时间扫描某博主最新的前 N 个帖子，并分别采集评论用户和点赞用户。

## 需求补充：评论用户采集（第一阶段）

本阶段在 `chrome_exp/fensi` 插件中只实现“评论用户”采集逻辑；“点赞用户”保留页面选项、视觉样式与结果位置，但不发起点赞用户请求，也不生成点赞用户结果。

### 请求流程

1. 先像粉丝功能一样打开目标博主主页，从页面已有的帖子 JSON 或帖子链接中读取最新帖子；若页面只有 shortcode，则在本地换算媒体 ID，不额外请求 `web_profile_info`。
2. 对每条待处理帖子请求评论接口：

   ```text
   https://www.instagram.com/api/v1/media/{media_id}/comments/?can_support_threading=true&permalink_enabled=false
   ```

3. 从响应 JSON 中读取：

   - `comment_count`：当前帖子的评论总数，用于显示进度并决定是否已取得全部评论。
   - `comments`：当前页评论数组；每条评论的 `user.username`、`user.full_name` 作为评论用户信息，数据结构与现有粉丝用户结果保持一致。

4. 首次响应的 `comments` 不足以覆盖全部评论时，扩展需要在对应帖子页面中识别并点击“加载更多评论”按钮，继续读取新加载的评论数据。

### 评论分页与结束条件

- “加载更多评论”按钮以可访问名称 `加载更多评论` 为识别依据，不依赖 Instagram 的易变 CSS 类名。
- 只要按钮仍存在且当前已获取评论数小于 `comment_count`，就继续加载并采集新出现的评论。
- 当“加载更多评论”按钮不再出现，或已获取评论数量达到 `comment_count` 时，停止当前帖子的评论采集。
- 对评论用户按用户名去重；同一用户在同一帖子多次评论、或在多篇帖子中评论，最终只保留一条用户记录。
- Instagram 返回的 `comment_count` 与实际可访问评论数不一致时，以页面不再提供“加载更多评论”为最终停止条件，保留已成功取得的数据并记录差异日志。

### 进度、结果与导出

- 进度至少显示当前帖子序号、该帖已收集评论数和 `comment_count`。
- 互动用户页面必须展示与现有“获取粉丝”页面一致的执行日志区域、显示时机、时间格式、最大保留条数与日志下载行为。
- 执行日志记录每帖媒体 ID、评论总数、每次“加载更多评论”的新增数及结束原因。
- 导出沿用粉丝结果的文本导出格式；评论用户文件名统一使用 `评论用户_` 前缀。
- 中断、接口失败或页面无法继续加载时，已收集的评论用户仍可导出。

### 点赞用户（暂不实现）

- 页面中仍展示“点赞用户”复选项和选中样式，以保持既定页面结构。
- 第一阶段选择“点赞用户”时应显示“点赞用户采集暂未开放”的提示；不请求点赞接口，也不影响评论用户的采集与导出。

## 页面与交互

- 页面顶部使用两个模式标签：“获取粉丝”和“获取帖子互动用户”。
- 默认选中“获取粉丝”，其原有用户名、提取数量与开始流程保持不变。
- 当前选中的模式使用亮粉色渐变、白色文字和投影，作为明确的主视觉状态。
- “获取帖子互动用户”模式包含博主用户名、扫描帖子数量（最小值 1，默认值 2）和两个可多选选项：评论用户、点赞用户。
- 至少选择一类互动用户才能开始；两个选项均取消时显示校验提示。
- 开始后进度改为“第 x / N 篇帖子”，并分别显示评论用户、点赞用户的累计去重数量。

## 数据与结果

- 帖子按 Instagram 返回的发布时间顺序处理，图文帖、视频帖和 Reels 均作为一篇帖子。
- 每类结果独立保留：`commentUsers` 与 `likeUsers`；同一用户在同一类中跨帖子重复出现时只保留一次。
- 评论与点赞结果不能互相覆盖；导出和复制操作应能明确选择评论、点赞或合并去重后的结果。
- Instagram 未返回完整分页数据、接口限制或用户主动停止时，保留已经成功取得的部分数据，并在日志和结果区明确标注完成原因。

## 后台采集边界

- 新流程沿用当前扩展在已登录 Instagram 标签页的 MAIN world 请求方式，避免由 popup 直接调用 Instagram。
- 先解析目标博主及其帖子列表，再逐篇处理评论用户；每个请求都携带会话标识、停止检查与进度日志。
- 评论请求使用接口返回的评论数据与页面“加载更多评论”按钮共同驱动分页；点赞分页逻辑留待后续阶段。
- 若 Instagram 因权限、隐私设置或接口策略不返回互动用户，流程仅报告该帖或该类型不可用，不伪造“已获取全部”的结果。

## 错误与停止

- 沿用现有登录过期、HTTP 429 退避、手动停止、弹窗关闭后终止和中断恢复的行为。
- 将失败上下文写入执行日志：帖子序号、互动类型和接口状态；其他帖子可继续时不让单帖失败丢弃已采集结果。
- 新模式的中断状态需要保存帖子索引、当前类型及各自游标，确保恢复时不重复处理已完成的数据。

## 登录验证需求

- 本次评论用户功能的登录验证使用 Instagram 账号密码登录，不依赖预置 Cookie。
- 测试账号的用户名与密码将由需求方后续补充到受控文档；实现中不得将密码、会话 Cookie、2FA 密钥或完整请求头写入页面、执行日志、导出文件或测试断言输出。
- 登录后再进入评论用户采集流程；若触发验证码、二步验证或 Instagram challenge，流程应停止并提示人工处理，不尝试绕过验证。

## 验证

- UI 测试覆盖默认标签、亮色选中状态、模式切换、互动类型至少选一项的校验。
- 后台测试覆盖帖子列表处理、评论/点赞独立去重、分别分页、部分失败保留结果和停止恢复状态。
- 页面测试覆盖互动模式下执行日志区的显示与写入格式，并确认其行为与现有粉丝日志一致。
- 集成登录测试使用需求方提供的账号密码；Cookie 为空时仍应进入账号密码登录流程，凭据不得出现在测试输出。
- 现有粉丝提取测试必须继续通过。

## 不在本次范围

- 不改变现有粉丝接口与粉丝采集逻辑。
- 不绕过 Instagram 的隐私设置、权限限制或未返回的数据。
